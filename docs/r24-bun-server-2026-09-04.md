# R24 独立 Bun 后端验收记录

日期：2026-09-04

## 结论

已在 `bun-server/` 交付独立 Bun 1.4 后端，同时保留 `server/` 作为 Node 生产与 Docker 基线。两套实现继续使用 Express 5、TypeScript 7、pnpm workspace 和同一个根 lockfile，对外 API、环境变量、认证规则、file/SQLite schema、Provider 语义和 NDJSON v2 协议保持一致。

本轮没有修改或运行 Docker。初始交付完成后按明确授权补跑了 Bun 全量 Mock 与 DeepSeek/OpenAI 真实 Provider，当前完成结论覆盖本机 Bun 1.4.0、Node 24.20.0 和 pnpm 11.16.0 下的静态、单元/API、隔离契约、Mock/真实 CDP、构建与观测基准。

## 设计边界

- `bun-server/` 不导入 `server/` 的业务源码；只与前端和 Node 后端共同使用框架无关的 `shared/chatStreamProtocol.ts`。
- Bun 首阶段只替换运行时和测试执行器，不改用 `Bun.serve`、`bun:sqlite` 或 Bun 包管理，也不生成第二份 lockfile。
- `server/data/` 与 `bun-server/data/` 默认隔离；并行启动时还必须使用不同端口。任何时候都不允许两个后端并发写同一个 file/SQLite 数据目录。
- `start:production`、Dockerfile、Compose、备份恢复脚本和生产部署说明继续指向 Node 后端。
- 回滚不需要数据迁移：停止 Bun 进程并继续使用 Node 后端即可。若要读取同一份既有数据，应先停止唯一写进程，再显式切换数据路径并完成备份。

## 实现组成

| 范围 | 实现 |
| --- | --- |
| 独立后端 | `bun-server/` 保持现有配置、middleware、route、controller、service、tool、adapter 和 store 相对边界 |
| 工具链 | `.bun-version` 固定 `1.4.0`；根 workspace/catalog/lockfile 纳入 `bun-server` |
| Bun 测试 | `tests/bun-server/` 分别导入 Bun 源码；runner 逐文件执行，隔离模块缓存与全局 mock |
| 运行时选择 | CDP helper 通过 `CHATBOT_SERVER_RUNTIME` 与 `CHATBOT_SERVER_DIR` 选择 Node/Bun，并适配 preload 参数 |
| 契约对照 | 隔离启动 Node/Bun，比较健康、runtime config、会话、NDJSON、重命名和重启后的持久化结果 |
| 观测基准 | 同机比较 5 次冷启动中位数、空闲 RSS、200 次健康请求 P50/P95 和首个流块延迟 |
