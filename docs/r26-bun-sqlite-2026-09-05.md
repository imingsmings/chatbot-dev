# R26 Bun 原生 SQLite 验收记录

日期：2026-09-05

## 结论

R26 已把 Bun 后端的会话 SQLite Store 和认证 Session Store 从 `node:sqlite` 切换为 `bun:sqlite`。现有 SQLite 路径、表结构、WAL、事务、环境变量、API 和 NDJSON v2 均保持不变；Node 后端继续作为过渡对照与可回滚基线。

本轮验证了旧数据库可由 Bun 直接打开，也验证了 Bun 写入后的同一数据库可重新交给 Node 使用。迁移不需要复制、转换或重建用户数据库。

## 实现范围

- `bun-server/utils/conversationStore/sqliteStore.ts` 使用 `bun:sqlite` 的 `Database`，保留原有建表、增量加列、JSON 迁移、健康探针和 `BEGIN IMMEDIATE` 事务语义。
- `bun-server/utils/authSessionStore.ts` 使用 `bun:sqlite`，保留认证 Session、Refresh Token 哈希、原子轮换、重放撤销和健康探针。
- Bun 数据库关闭使用 `close(true)`，在测试重开和进程退出边界立即终结未释放 Statement。
- `bun-server/tsconfig.json` 只增加 `bun-types/sqlite`，不引入会改变现有全局 `fetch` 类型的完整 Bun globals。
- Bun SQLite 测试移除 `node:sqlite` 可用性探测和跳过逻辑，旧 schema 夹具也由 `bun:sqlite` 创建。
- 工具链守卫扫描 Bun 业务源码和 Bun 测试，阻止以后重新引入 `node:sqlite`。

未修改 Node `server/`、Express 路由、Provider adapter、前端协议、环境变量、持久化 schema 或附件格式。

## 兼容与回滚门禁

`tests/runtime/sqlite-runtime-compatibility.mjs` 使用同一临时数据目录执行：

1. Node 后端通过 `node:sqlite` 创建会话并完成一次 Mock Provider 请求。
2. Bun 后端通过 `bun:sqlite` 直接读取该会话、更新标题并写入新会话。
3. Node 后端重新打开同一数据库，读回 Bun 的更新和新增记录。
4. 三次运行合计只调用一次 Mock Provider，证明切换运行时不会重放已持久化请求。

`tests/runtime/backend-parity.mjs` 同时覆盖 file 和 SQLite 两种 Store，比较 Node/Bun 的健康检查、运行配置、会话 API、NDJSON v2、重命名与重启持久化。

## 测试中修复的门禁缺陷

- Bun 全量测试首次通过时，Vision 测试 teardown 与上传后的异步孤儿附件清理发生竞态，产生非致命 SQLite I/O 警告。测试现在先等待一次清理并关闭 Store，再恢复环境变量和删除临时目录；Vision 专项连续五次及随后 Bun 全量均无该警告。
- 首次全量 Mock 的 upstream-abort 场景把测试会话 ID 存在页面全局变量中，导航后状态丢失。门禁改为从 CDP `Network.getResponseBody` 记录 POST 创建结果，不依赖页面生命周期；取消专项连续两次以及随后无重试全量均通过，原有取消、上游释放和持久化断言未放宽。

## 验证边界

- 未调用 DeepSeek/OpenAI 真实 Provider。R26 只替换本地 SQLite 驱动，Provider 请求形状和流协议未改变；真实功能证据继续沿用 R24。
- 未运行 Docker。当前生产启动和 Docker 仍使用 Node/pnpm 旧链路，统一迁移保留到 R29。
- 未迁移到 `Bun.serve`，Express/HTTP/HTTPS/multipart/静态文件和流式背压仍属于 R27。
- 未删除 Node 后端、Node 测试或 parity；删除对照链路属于 R28。

## 风险与回滚

当前剩余风险集中在尚未迁移的 HTTP 和部署边界，不在 SQLite 文件兼容性。需要回滚 R26 时，仅恢复 `bun-server` 的 `node:sqlite` adapter 和对应类型/测试即可；已验证 Node 能直接读回 Bun 写入的数据库，不需要数据回滚。

下一阶段是 R27：让 `Bun.serve` 接管 HTTP/HTTPS 边界，同时保持现有 Express 路由语义、API、multipart、静态文件和 NDJSON v2 行为。
