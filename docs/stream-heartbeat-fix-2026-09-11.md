# 流式保活修复与提交验证

## 原因与修改

此前 OpenAI 长回答测试在人工停止之前，浏览器 15007ms 内未收到响应数据，触发客户端 15 秒空闲保护。后端原本只在正文、reasoning、工具或终态事件出现时发送数据，无法区分模型等待与连接失活；旧日志不足以定位 Provider 内部或代理延迟。

- 新 ask 接受后立即发送 NDJSON 空行，执行期间约每 5 秒保活。
- 空行不生成消息、不落库、不改变六种业务事件；前端 15 秒断线保护和后端 Provider 超时均保持不变。
- 写入等待背压，最多一个保活写入等待；结束、取消或连接关闭时清理。
- OpenAI 真实脚本增加错误终态快失败，并分别记录传输首字节与业务首事件，避免把保活误当作模型输出。

## 已执行验证

- 2026-09-08：Bun + Vite + Chrome CDP、本地 Mock 上游静默 18 秒；16 秒时应用读取 4 次空行、无正文及错误；之后停止释放上游并保存 2 条消息，同会话恢复后 4 条。TC-01/02/04/08/09/10 全部通过。
- 同日全量 Mock 首轮在主题刷新时遇到 CDP 执行上下文销毁；补充刷新完成等待，保留原断言后完整复跑 20/20，全部 attempt=1。最终结果时间为 `2026-09-08T01:26:00.717Z`。
- 提交前重新执行：`bun run check`、`bun run test:unit`（后端 184、前端 139）、`bun run test:toolchain`（7 项）、`bun run build:client` 均通过。
- 历史失败与本地保活证据保留于 `.tmp/openai-heartbeat-fix-2026-09-08/`；全量 Mock 最终结果位于 `.tmp/cdp-results/all-mock.json`，这些本地诊断产物不提交。
